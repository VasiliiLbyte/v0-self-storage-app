Проверь: $ARGUMENTS

Протокол: `hub/playbook/VERIFY.md`. Свою же реализацию не принимай на слово.

1. Прочитай файл задачи `hub/tasks/*<ID>*.task.md`. Выпиши критерии из §5 и стоп-сигналы из §4.
2. **Код.** `git diff main...HEAD --stat` и `git diff main...HEAD`. Прочитай изменённые файлы
   целиком. Сверь со скоупом, со списком «НЕ трогать» и красными флагами VERIFY §4.
3. **Типы и сборка.** Запусти `npx tsc --noEmit` и `npm run build`. Сохрани вывод.
4. **API.** Если задеты `app/api/**`: подними `npm run dev` в фоне и сделай curl —
   happy path, кривой body, без сессии, чужая сущность. Сверь с `hub/API_CONTRACT.md`.
5. **Живой UI.** Пройди сценарий задачи в браузере на 1280px и 375px, посмотри консоль и сеть.
   Пройди обязательные регрессии по области (VERIFY §2).
6. **Данные и безопасность.** Для БД и денег: идемпотентность миграции, RLS, сумма на сервере,
   повторный webhook.
7. Заполни в файле задачи раздел «Отчёт о проверке»: по каждому слою — как проверял
   и что получилось, чеклист критериев.

Итог:
- **verified:** статус задачи в PROGRESS → `verified`, строка DEP-NNN в «Ожидает деплоя»
  (ветка, SHA, миграции), блок деплоя по `hub/templates/DEPLOY_BLOCK.md`, строка в логе сессий.
- **не готово:** пронумерованный список «файл:строка — что не так — что ожидается — как проверить».
  Чини и проверяй заново.

Оператору сначала итог одной строкой, потом детали. Если задача про деньги, RLS или auth,
предложи `/code-review` по ветке перед merge.
