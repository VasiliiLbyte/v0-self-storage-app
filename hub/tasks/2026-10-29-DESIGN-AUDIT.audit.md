# DESIGN-AUDIT: единый стиль и UI всех страниц (2026-10-29)

**Итог:** 9 × P0, 10 × P1, 9 × P2.

**Что проверено:** локальный `npm run dev` (ветка `fix/sec-booking-price`), 1280×800 и 375×812,
светлая и тёмная темы. Живьём: `/`, `/storage-units`, `/booking` (шаг 1), `/auth/login`,
`/auth/signup`, `/auth/signup-success`, `/legal/*`, `/legal/contract`, 404.
По коду: личный кабинет `/dashboard/*` и админка `/admin/*`.

**Не проверено живьём:** кабинет, админка, шаги 2–4 бронирования, `/booking/success`, каталог
с данными. Причина: Supabase из `.env.local` не резолвится (блокер #3 в PROGRESS).

> Скриншоты снимались с принудительной видимостью анимированных элементов: в фоновой
> вкладке framer-motion не доигрывает анимации. Это само по себе находка, см. P0-4.

## Что уже хорошо

- Одна палитра на токенах shadcn (oklch): оранжевый `primary`, тёмно-синий текст, нейтральные поверхности.
- Узнаваемый паттерн секций: оранжевый «eyebrow» капсом (ПРОЦЕСС, КАЛЬКУЛЯТОР, ПРЕИМУЩЕСТВА, ОТЗЫВЫ, FAQ, ЛОКАЦИЯ) + крупный заголовок.
- Акцентная «первая карточка» в оранжевом (преимущества, отзывы) — повторяемый приём.
- Шаги бронирования, калькулятор с липким итогом, карточки на `rounded-2xl` — аккуратно.
- Горизонтального скролла на 375px нет.

## Предлагаемые пакеты работ

Порядок — по отдаче и риску. Каждый пакет — отдельная задача по `hub/templates/TASK.md`.

1. **DESIGN-THEME-TOKENS** (P0-1…3, P0-9): токены `accent` / `inverse`, `next-themes`, `themeColor`. 3–5 файлов, без изменения разметки страниц.
2. **DESIGN-QUICK-FIXES** (P0-4…8, P1-7…10): отступ legal, title, остатки бренда, анимации первого экрана, типографика чисел, эмодзи, контраст.
3. **CONTENT-TRUST** (P1-1…4): нужны факты от оператора — реальные цифры, отзывы, контакты, страховка; цены калькулятора из БД. Связано с CONTENT-CONTACTS.
4. **UI-STATUS-FEEDBACK** (P0-8, P1-5, P1-6): `StatusBadge`, единые подписи, тосты вместо `alert()`.
5. **UI-SYSTEM** (P2-1…3): `PageContainer`, уровни заголовков, вариант CTA-кнопки.
6. **UI-APP-SHELL** (P2-4, P2-5): общая оболочка кабинета и админки. Делать после того, как появится рабочий Supabase для живой проверки.
