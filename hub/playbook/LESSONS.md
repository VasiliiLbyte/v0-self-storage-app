# Уроки: правила, которые появились после ошибок

Общая часть взята из Control Hub Kit (уроки чужого прода). Уроки этого проекта внизу.
Свои уроки дописываются в конец файла.

## Процесс

| Что случилось | Правило |
|---|---|
| Исполнитель в отчёте написал «всё работает», а сборка на сервере упала | Отчёт не доказательство. Build и typecheck запускаются на деле, в отчёт идёт вывод |
| Задачу приняли, а через неделю вспомнили, что оператор решал иначе | Решения оператора записываются в файл задачи и в `DECISIONS.md` в момент принятия |
| «Небольшой рефактор заодно» сломал соседний экран | План со списком «НЕ трогать» до кода |
| Журнал разросся до сотен килобайт, агенты перестали читать его целиком | Ротация `PROGRESS.md` в `archive/` раз в месяц |
| Задача ссылалась на «как мы обсуждали», агент в новом чате придумал своё | Файл задачи самодостаточен: пути, якоря в коде, критерии и команды внутри него |

## Git и терминал

| Что случилось | Правило |
|---|---|
| `git push origin feature # комментарий` в zsh: комментарий ушёл как refspec | В блоке команд нет inline-комментариев. Пояснения над блоком |
| `cd ~/code /repo` из-за пробела в имени папки ушёл не туда | Пути с пробелами всегда в кавычках. У этого проекта путь `/Users/vasilii/Desktop/code /pelikan-storage` |
| Спецсимволы в `git commit -m` сломали команду | Сообщение коммита через HEREDOC |
| Опечатка в пути `git add` дала пустой коммит | После `git add` — `git status`, после коммита — `git show --stat` |
| После `git reset --hard` пропали записи журнала | `reset --hard`, `clean` и force-push запрещены |

## Деплой

| Что случилось | Правило |
|---|---|
| Поправили env, а процесс работал со старыми значениями | На Vercel после правки env — Redeploy. `NEXT_PUBLIC_*` вшиваются при сборке |
| Новый код начал валидировать поле, которого не было в старых строках | Миграция применяется до кода |
| Сразу после деплоя 502, начали откатывать | Сначала дождаться Ready и минуту прогрева |

## Данные

| Что случилось | Правило |
|---|---|
| Структуру каталога взяли с сайта, где был баг рендера | Источник правды — БД. Сайт — симптом, а не факт |
| SQL-правка `WHERE slug = …` задела лишние строки | Массовые правки по `id`, с бэкапом и предварительным `SELECT count(*)` |

## Уроки Pelikan Storage

| Дата | Что случилось | Правило |
|---|---|---|
| 2026-06 | Пользователей выкидывало из аккаунта через несколько секунд после логина на Vercel. Браузерный клиент Supabase и middleware одновременно обновляли refresh-токен, сработал reuse detection, сессия отзывалась (`15f9b33`, `d1903e8`, `86b5c90`) | Токен обновляет **только** middleware. В `lib/supabase/client.ts` остаются singleton и `autoRefreshToken: false`. В браузере `getSession()`, а не `getUser()`. Matcher middleware только на `/dashboard`, `/admin`, `/booking` |
| 2026-06 | Prefetch ссылки «Выйти» вызывал `signOut` и разлогинивал пользователя (`6a6f384`) | Выход только `POST` формой. Middleware пропускает prefetch-запросы, не обновляя сессию. Действие с побочным эффектом никогда не делается на `GET` |
| 2026-10 | Цена брони и статус пишутся из браузера, а RLS это пропускает (SEC-BOOKING-PRICE) | RLS «своя строка» не защищает денежные поля. Суммы и статусы ставит сервер (route handler или service role), клиенту — только поля, которые он вправе менять |
